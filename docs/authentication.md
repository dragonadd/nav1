# 后台双模式登录

后台入口为 `/system`；Hash 模式使用 `/#/system`，部署在子目录时保留子目录前缀。

## 登录行为

- 没有 `data/auth.json`、文件空白或返回 404 / 204：只提供 Token 登录。
- 有合法凭证：默认密码登录，可以切换 Token 登录。
- 网络失败、超时、HTML 回退或损坏密文：明确提示错误，保留 Token 登录和重新读取配置。
- 密码解密成功后仍验证 Git 用户和仓库权限。GitHub / Gitee 检查 `permissions.push`，GitLab 检查项目 / 组角色至少为 Developer；归档仓库拒绝登录。
- 有独立图床时验证其凭证，全部成功才保存会话。同一平台使用主 Token，跨平台使用独立图床 Token，并一起加密。
- 自有服务器部署使用服务器的 `password`，不启用静态凭证密码管理。

仓库权限不能证明 Token 的全部 scope、图片分支及分支保护要求已经满足；实际写入由 Git 平台校验。

## 密码管理

在 **后台 → 登录密码管理** 填写新密码和确认密码。密码至少 8 个字符并包含字母和数字，推荐 12 位以上的独有随机密码或更长口令。

密码用于 PBKDF2-SHA-256（600,000 次）派生不可导出的密钥，AES-256-GCM 加密当前主 Token 和必要时的图床 Token。每次使用随机 16 字节 salt、12 字节 IV 和 128 位认证标签。凭证使用 `nav-auth` v1 格式，认证附加数据绑定主仓库、图床、平台和实际配置分支。

仓库的 `data/auth.json` 只包含格式、版本、算法参数、salt、IV 和密文，不含明文 Token、密码或密钥。它通过现有 Git API 单独提交；修改 / 删除携带读取版本，冲突要求刷新并保留输入。普通站点设置的保存不会修改凭证。

提交成功后，必须等待当前分支重新构建并部署成功。登录请求的时间戳不能读取尚未发布的新版本。若密码解密后 Git 返回 401，使用有效 Token 登录当前分支，重新设置密码并等待部署。

默认 `branch: auto` 在构建时识别实际部署分支，支持任意合法分支名，后台内容和密码均保存到该分支。分支也是密文身份和会话的一部分：更换部署来源后，先在目标分支重新部署，用有效 Token 登录并重设密码，再等待部署成功。不同分支的密文和会话不会自动互相迁移。

“移除密码”需要确认并删除仓库凭证；部署成功后只提供 Token 登录。

## 会话与构建

主 Token 和独立图床 Token 只保存在当前标签页的 `sessionStorage`，按站点子路径、仓库配置、分支、图床和服务器地址隔离。升级清除旧 `localStorage.token` / `IMAGE_TOKEN`，不迁移旧明文凭证，需要重新登录。密码和派生密钥不写入浏览器存储；信息页不显示明文 Token。

刷新保留登录，退出清除会话。复制标签页或浏览器恢复会话可能继承存储，不能保证关标签后绝对不可恢复；需要明确清理时点击退出登录。

初始化严格校验源凭证，生成 `src/generated/auth/auth.json`，Angular 单独发布到 `data/auth.json`。空白 / 移除会清理生成资源；无效或明文文件会阻止构建。凭证不并入导航数据、站点设置、搜索或 SEO 正文。

读取使用时间戳、`cache: no-store`、`credentials: omit`、8 秒超时，以及 Angular Service Worker 的 `ngsw-bypass`。Netlify、Vercel 和 Cloudflare Pages 配置凭证响应头 `Cache-Control: no-store`；其他 CDN 的缓存策略需要按实际托管配置。

## 保护边界

这是密码解锁 Git 写入凭证的便利入口，不能替代服务器账号系统。公开站点的密文可以下载后离线猜解，私有仓库也不隐藏已经部署的密文，请使用独有强密码和只授权必要仓库的专用 Token。

换密码或删除文件不能消除 Git 历史、旧部署和已经下载的密文，也不能撤销其中的 Token。需要撤销旧密码的访问能力时，先在 Git 平台撤销 / 轮换 Token，再用新 Token 登录并设置新密码。

`sessionStorage` 无法阻止同源恶意脚本读取 Token。自定义 head / footer HTML、组件 HTML 和可执行脚本必须可信；密码加解密使用 HTTPS 或 localhost。导航的“登录后显示”标记只是前端显示控制，不是静态数据保密机制。

## 验证

`pnpm test` 覆盖密码规则、真实加解密 / 身份隔离、会话、公开配置错误、权限校验、三平台凭证请求和冲突保护，以及临时目录的凭证生成 / 清理。

先构建网站，再运行 `pnpm run test:auth-bundle`，验证真实生产产物在独立路径发布密文、其他公开资源没有测试明文凭证，并恢复普通构建、清理测试资源。

先构建网站，再运行 `pnpm run test:auth-ui` 检查真实浏览器中的两种登录、密码管理和手机布局。设置 `NAV_TEST_HASH_MODE=1` 可验证 Hash 路由。测试使用测试 Token 和内存 API，不提交远程凭证。
