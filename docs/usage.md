# 使用说明

[返回项目介绍](../README.md) · [English](usage_EN.md)

## 登录与保存

后台入口为 `/system`，Hash 路由使用 `/#/system`。首次以有仓库写权限的 Token 登录，之后可以在“登录密码管理”设置密码。跨平台图床需要独立的图床 Token。

网站编辑先更新当前浏览器中的内容。在“网站管理”点击 **保存** 后，数据会提交到构建时确定的 Git 分支。连接 Git 的托管平台完成部署后，刷新即可看到公开内容。

密码设置、修改和移除也需要等待部署。使用强密码和专用 Token；忘记密码时用有效 Token 登录重新设置。详细安全边界见 [后台登录机制](authentication.md)。

## 分类、网站与标签

- **一级分类**用于组织资源分组，**二级分类**用于页面导航，**三级分类**用于收纳网站。
- **网站管理**默认列出全部网站，可以搜索名称、网址和描述，再按分类或异常状态筛选。
- 选定三级分类后可以添加网站；清空搜索并退出异常筛选后，可以调整该分类内的网站顺序。
- 编辑、移动、引用和批量删除使用相同的导航数据。批量操作只作用于当前列表可见的勾选项。
- **标签设置**用于维护标签名称、颜色、顺序和附加链接；编辑网站时选择相应标签。
- Side 卡片右上角提供登录后的编辑按钮。访客操作权限在 **系统设置 → 高级设置** 配置。

分类链接如 `/side?id=3` 可以收藏和分享。重复点击同一分类保持同一地址。分类 ID 应以自己的导航数据为准。

“登录后显示”属于页面展示控制；发布后的静态数据可能被直接读取。

## 分类图标

在 **网站管理 → 一级 / 二级 / 三级分类 → 编辑** 中填写图标。

支持图片网址和 Font Awesome Free 6 类名，例如：

```text
https://example.com/icon.png
fas fa-film
fab fa-github
fa-solid fa-book
```

编辑窗口提供预览。Side 和 Super 的二级分类图标使用该分类自己的配置；Font Awesome 字体随网站构建发布。

## 主题与站点设置

系统设置分为五个分栏：

| 分栏       | 内容                                                   |
| ---------- | ------------------------------------------------------ |
| 基础信息   | Logo、标题、网站描述、关键字、语言、联系邮箱和图片 CDN |
| 外观与交互 | 搜索、快捷工具、加载动画、组件和手机 PWA               |
| 主题设置   | 默认主题、手机主题，以及各主题的横幅、卡片和页脚       |
| 每日文字   | 一言来源、自定义文字、标题、出处和字数上限             |
| 高级设置   | 访客权限、快捷键、保存请求、自定义 HTML 和爬取规则     |

**保存**会提交所有分栏中的修改。网站描述用于 SEO，主题页面标题留空时使用全局标题。自定义 HTML 应使用可信内容。

Side 支持横幅搜索、分类侧栏和网格卡片；其标题、横幅、页面标题及页脚在 **主题设置 → Side** 配置。其他主题可在对应页签设置。手机主题可独立选择，或跟随当前页面。

## 每日一言与每日文字

在 **系统设置 → 每日文字** 配置。卡片显示在 Side 横幅下。

| 来源名       | 内容         |
| ------------ | ------------ |
| `hitokoto`   | 一言         |
| `jinrishici` | 今日诗词     |
| `xygeng`     | 随机句子     |
| `60s`        | 每日新闻     |
| `history`    | 历史上的今天 |

最多配置五个来源，每行一个；每个来源的显示上限为 100–4000 字。自定义接口支持 JSON、数组和纯文本，可指定显示名和字段路径：

```text
hitokoto
我的句子 | https://example.com/quote | data.content
```

末尾加 `| 正文` 隐藏出处，加 `| 出处` 显示出处。接口必须允许浏览器跨域访问；HTTPS 网站使用 HTTPS 接口。

只使用自定义文字时，将接口来源留空。自定义文字支持多行内容和 `{date}`、`{time}`、`{weekday}`、`{month}`、`{day}` 变量，例如：

```text
今天是 {date}，{weekday}。
留一点时间，探索新的事物。
```

日期和时间按访客浏览器本地时间更新。关闭标题保留正文；关闭总开关则不显示卡片，也不请求接口。各来源独立按天缓存，某个来源失败不影响其他内容，点击“重试”可重新获取失败来源。

## 备份与导入

在“网站管理”下载 JSON 备份；备份包含导航、设置、标签、搜索和组件数据。导入备份会替换相应数据，请先保存自己的备份。

浏览器收藏可通过“书签导入”导入 HTML 文件。“撤销本次所有操作”恢复当前发布版本并清除本地编辑。

## 仓库与图床配置

配置文件为 [nav.config.yaml](../nav.config.yaml)。

| 字段           | 用途                                      |
| -------------- | ----------------------------------------- |
| `gitRepoUrl`   | 导航源码和数据所在的仓库                  |
| `branch`       | `auto` 跟随部署分支；也可显式填写提交目标 |
| `imageRepoUrl` | 图床仓库，查询参数 `branch` 指定图片分支  |
| `hashMode`     | Hash 路由开关                             |
| `address`      | API 服务器地址；静态部署保持空值          |
| `email`        | 收录通知邮箱，依赖对应通知服务            |

GitLab URL 需要项目 ID，例如 `https://gitlab.com/USER/REPO?projectId=123`。图床还可指定分支：`https://gitlab.com/USER/IMAGES?projectId=456&branch=images`。

提前创建图床仓库和分支，授予 Token 相应写权限。同平台图床使用主 Token；跨平台图床需要独立 Token。

使用 API 服务器模式时，需要另外提供兼容服务器；服务器的 `password`、`port`、`mailConfig` 等字段按该服务配置。静态登录密码在后台管理，Token 和密码不应写入普通设置或 YAML。

## 验证与升级

`pnpm test` 覆盖每日文字、图标、配置迁移、部署分支和后台凭证。生产构建后可以运行 `pnpm run test:auth-ui`、`pnpm run test:themes`，以及检查凭证发布资源的 `pnpm run test:auth-bundle`。

Hash 登录检查使用环境变量 `NAV_TEST_HASH_MODE=1`；PowerShell 可设置 `$env:NAV_TEST_HASH_MODE = '1'`。浏览器检查使用测试凭证和内存 API。

升级前备份 `data/` 与 YAML，检查源代码和配置差异。更换部署分支后，在新分支用 Token 登录并重新设置密码。
